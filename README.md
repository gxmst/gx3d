# GxEngine

GxEngine 是一个学习型 Rust 3D 引擎 / FPS sandbox。当前目标不是做成通用商用引擎，而是用尽量清楚的模块边界串起一个可运行、可调试、可继续扩展的 3D 游戏骨架。

## 当前状态

- Rust 2021 + winit + wgpu 窗口和渲染主循环
- hecs ECS 世界、资源容器和分阶段调度器
- Rapier3D 物理世界、刚体/碰撞体、射线检测、CCD、运动学角色控制器与固定步同步
- PBR 前向渲染、方向光阴影、程序化 IBL、SSAO、Bloom、ACES 后处理
- 程序化几何体和基础 glTF/GLB 静态网格加载
- FPS 摄像机、带台阶/坡面/土狼时间/跳跃缓冲的玩家移动、射击与手动装填、后坐力、独立路线敌人 AI
- 物理 sandbox：质量差异、摩擦/弹性材质、坡道、冰面、滑块、可击倒靶、生成/拾取/投掷动态物体，以及防穿墙的实体形状扫掠
- 数据驱动场景：关卡几何体、材质、灯光、敌人布局从 `assets/scenes/*.json` 加载，改场景不用重新编译。启动场景是 dust2 风格关卡
- 击中反馈：射击命中敌人会触发高亮闪光 + 顿挫 + 击退，击杀生成发光爆点并清除物理体
- 完整游戏内 HUD 与响应式双栏设置菜单：弹药/装填、模式、倍速、FPS、坐标、灯光/刚体统计、持物状态和调试图层均在画面内可见
- 可射爆油桶：爆炸按距离衰减、受墙体遮挡，并对可见敌人和动态刚体施加伤害/冲量

## 运行

```powershell
cargo run
```

可直接选择场景（名称会从 `assets/scenes/` 解析，也可传完整路径）：

```powershell
cargo run -- --scene sandbox
cargo run -- --scene assets/scenes/dust2.json
```

首次构建会比较慢。FPS、弹药、灯光数量、相机位置和物理状态显示在游戏内 HUD。
启动时默认创建 1920×1080 的窗口化画面并居中，鼠标会进入 FPS 锁定/隐藏状态。主循环最高 144 FPS。

## 启动场景：dust2 风格关卡

启动加载的是一张按 Dust II 经典空间关系重做的原创练习关卡（不使用 CS 原始资产）：包含 T 出生点、中路双门与 Xbox、猫道/小道、A 大门与长 A、A 坡和 Goose、B 洞、B 门与车位、CT 坡及两个清晰标色的包点。场景现有 **285 个实体、31 种材质和 9 盏灯**，加入棚架、护栏、脚手架、仓储区、储罐、沙袋、空调、排水、电气、招牌、车辆细节、屋顶设备、实体管线、苔藓、分层涂鸦和可互动道具。T 出生区设有一组不同质量和弹性的球，可观察连锁碰撞。

- 对准程序化人形假人射击：命中会**白色高亮闪光 + 顿挫 + 轻微后退**；血量打光后假人**原地爆出一簇发光球并消失**（物理体一并移除，不留幽灵碰撞）。
- 命中点会留下短暂闪光和约 12 秒的弹孔。
- 地图分布 8 个动态爆炸桶；墙体会遮挡爆炸冲量和伤害，适合配合暂停/单步观察连锁反应。
- 散落的木箱、金属油桶是动态物体，可被射击击退、抓取和投掷。运行时生成物最多保留 96 个，超出后自动清理最旧物体及其碰撞体。
- 四名假人使用各自区域的巡逻路线；移动前会用自身胶囊扫掠，路线受阻时会自动换下一个目标点。

`E` 或中键对准动态物体可抓取，滚轮拉近/推远，`T` 可以把持物抛出去。`G` / `B` / `H` 可在准星前生成箱子 / 弹力球 / 重箱。
设置菜单打开时会释放鼠标，采用响应式双栏布局显示设置和键位；720p、1080p、1440p 与 3440×1440 均有对应布局。
分辨率列表包含 3440×1440（21:9），适配常见 34 英寸 2.5K 超宽屏。

`assets/scenes/sandbox.json` 仍保留为另一张物理 playground 场景，可用 `cargo run -- --scene sandbox` 直接启动，无需修改代码。

## 观察与实验

- `V` 可随时在 FPS 和上帝自由飞行模式之间切换，世界和物理模拟不会重建或中断；设置菜单中可关闭上帝模式。
- `P` 暂停后仍可自由飞行观察，按 `.` 每次只推进一个固定的 1/60 秒物理帧。
- `[` / `]` 在 0.1×、0.25×、0.5×、1×、2× 之间调速。倍速只改变固定帧触发频率，不改变 Rapier 的物理步长。
- `F3`、`F4`、`F5` 分别叠加碰撞体、速度向量、接触信息；可与暂停和单步组合观察碰撞瞬间。
- 天空由实时 shader 生成蓝天、地平线、太阳盘和移动云层；太阳约每六分钟完成一次昼夜循环，并同步改变方向光与阴影方向。
- 天空视线由相机的世界空间前/右/上基向量构造，不依赖相机平移或不稳定的逆矩阵重建。
- 动态刚体带有线性和角阻尼，球体会逐渐停止；球面细节使用物体空间和 UV 生成，会随球真实滚动。
- 上帝模式和 FPS 模式都可用现有的抓取、投掷、冻结和生成操作；`Delete` 删除准星下的动态物体并同步清理其碰撞体。
- 抓取采用固定物理步的限速阻尼跟随，并用物体真实碰撞形状扫掠到目标点；轻球不会因刷新率变化突然飞走，大物件也不会被拉过薄墙或拐角。
- 准星指向可交互物体时会显示名称、距离和可用操作；中门与 A 大门可用 `E` 平滑开关，门围绕真实铰链转动，关闭遇到玩家或动态物体会自动回开。

## 编辑场景

关卡现在是数据驱动的：场景内容（材质、关卡几何体、灯光、敌人布局、玩家出生点）写在 `assets/scenes/` 下的 JSON 里，**改这个文件不需要重新编译**。启动场景是 `dust2.json`；引擎优先读取磁盘上的该文件，读不到或解析失败则回退到嵌入二进制的同一份默认场景，并打日志说明原因——场景写错不会让引擎崩溃。

格式要点（对手写友好）：

- 网格和材质先在 `meshes` / `materials` 里**起名字**，实体再用名字引用。
- 网格来源可用程序化生成器（`cube` / `sphere` / `cylinder` / `plane` / `rifle`），也可用 `{"gltf":{"path":"assets/models/model.glb","primitive":0}}`。glTF 节点层级变换会烘焙进网格。
- glTF 实体把 `material` 写成 `"$gltf"` 会使用该 primitive 自带的 PBR 材质；也可填写场景材质名称进行覆盖。
- 旋转用**欧拉角（度）**，不是四元数。
- 物理表面可填预设字符串（`"default"` / `"ice"` / `"rubber"` / `"metal"`）或裸对象 `{"friction": ..., "restitution": ...}`。
- `mass` 为 0（或省略）即静态物体；`initial_impulse` 可给出生时一次性冲量。
- 门交互可配置 `open_rotation`、`hinge_offset` 和 `speed`；敌人既可使用共享 `waypoints`，也可按出生点配置独立 `routes`。
- 危险的细分、尺寸、材质、灯光、玩家与交互参数会在加载边界被限制到安全范围；缺少引擎约定网格/材质时会生成真实的程序化回退资产，不会用空句柄进入渲染阶段。

引擎管线（玩家胶囊、武器、命中反馈材质、GPU 上传、音频）仍在代码里，按名字从场景取所需句柄，因此 `cube` / `sphere` / `rifle` / `box` / `ice` 等名字是引擎约定依赖的。

## 架构笔记

- `src/core`：ECS 包装、资源容器、时间和调度。
- `src/renderer`：wgpu 初始化、渲染管线、bind group、后处理、SSAO、IBL。
- `src/physics`：Rapier3D 封装、碰撞形状、射线和物理 sandbox。
- `src/asset`：网格、材质、纹理、程序化资源和 glTF 加载。
- `src/game`：当前 FPS sandbox 的玩家、武器、敌人和系统注册。
- `src/game/scene`：数据驱动场景的数据结构（`mod.rs`）和实例化逻辑（`spawn.rs`）。
- `assets/scenes`：JSON 关卡文件。`dust2.json` 是启动默认场景（同时被嵌入二进制做兜底），`sandbox.json` 是物理 playground。
- `assets/shaders`：WGSL shader。主 PBR pass 输出线性 HDR，tone mapping 在后处理完成。
